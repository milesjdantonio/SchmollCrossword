# Schmoll Crossword

A free mini crossword **website**, inspired by **The New York Times Mini Crossword**.

The player gets a 5×5 grid with a few black squares and a list of clues (1-Across, 1-Down, …). They click squares, type letters and fill in the words. When every square is right, the puzzle is solved and they get a time and a score.

- **Daily mode:** one puzzle per day, the same for everyone.
- **Unlimited mode:** a fresh puzzle whenever you want.
- **Saved in your browser:** progress, scores, streaks, stats and settings (difficulty, harder words, timer, theme).

What makes this project different: **the puzzles are generated by the program.** The computer fills the grid with everyday words, numbers the squares, and has Claude write a fresh clue for each answer at the chosen difficulty.

> This is a learning project, built step by step with help from Claude ("vibe coding"). The roadmap below shows every step of the full game and marks where things currently stand.

## How the game works

### For the player
1. Open the website and pick **Daily** (today's puzzle, the same for everyone) or **Unlimited** (a new puzzle each time), at easy, medium or hard.
2. Click a square (or a clue) to select a word. The current word is highlighted.
3. Type letters. The cursor moves to the next square. Click the selected square again to switch between Across and Down.
4. Use **Check** to see wrong letters, or **Reveal** to give up on a square, word or the whole puzzle.
5. Fill every square correctly → a "You solved it!" screen with your time and score. Stats, streaks and settings are saved in your browser.

### Behind the scenes (the puzzle generator)
1. **Load a word list** and sort the words into buckets by length.
2. **Pick a grid shape:** 5×5 with black squares (`true` = black, `false` = open).
3. **Find the slots.** A *slot* is a run of 3+ open squares going across or down. Each slot holds one answer.
4. **Fill the slots** one by one, using the letters already placed (the *pattern*, e.g. `C.T`) to find words that fit.
5. **Backtrack** when stuck: undo the last word and try the next option.
6. **Number the squares and attach clues** to each answer.
7. **Send the finished puzzle to the game screen** for the player to solve.

## Roadmap

Legend: ✅ done · 🔨 **in progress (you are here)** · ⬜ not started

> For what each step teaches and its related LeetCode problems, see [ROADMAP.md](ROADMAP.md).

### Phase 1: Foundations
- ✅ **Step 1: Project setup.** Maven project, `com.crossword` package, Java 17.
- ✅ **Step 2: Load the word list.** `App.loadWords()` reads `words.txt` and groups words by length into a `Map<Integer, List<String>>`.
- ✅ **Step 3: Represent the grid.** `boolean[][] blackSquares` for the shape, `char[][] filledGrid` for the letters (`.` = empty).
- ✅ **Step 4: Find all slots.** `Slot.findAcrossSlots()` / `findDownSlots()` scan each row/column for runs of 3+ open squares.
- ✅ **Step 5: List a slot's squares.** `Slot.getCells()` returns the `(row, col)` of every square in a slot.

### Phase 2: Generate a filled grid
- ✅ **Step 6: Read a slot's pattern.** `Slot.getPattern(char[][] filledGrid)` walks the slot's squares and builds a string like `"C.T.."` from the grid.
- ✅ **Step 7: Find matching words.** `App.findMatches(pattern, wordsByLength)` pulls the bucket for the pattern's length and keeps every word that fits (`.` matches any letter). Tested with PASS/FAIL checks in `main`.
- ✅ **Step 8: Place and remove words.** `Slot.placeWord()` writes a word along a slot and returns only the squares it filled. `Slot.removeWord()` blanks just those squares, so letters shared with crossing words stay put.
- ✅ **Step 9: Backtracking solver.** Recursive `App.solve(slots, index, grid, words)` fills slot `index`, tries each matching word, calls itself on `index + 1` and undoes the word on a dead end. Slots are tried in alternating across/down order so crossings are checked early (all-across-first never finished).
- ✅ **Step 10: No repeated answers.** `solve` takes a `Set<String> usedWords`: skip candidates already in it, add on place, remove on undo. (Without it, the first grid was a mirror image with every word used twice.)
- ✅ **Step 11: Print the filled grid.** `App.formatGrid(filledGrid, blackSquares)` returns the grid as text with `#` for black squares and single spaces between squares.
- ✅ **Step 12: Faster and different every time.**
  - ✅ **12a: Shuffle.** `solve` takes a `Random` and shuffles each slot's candidates, so every seed gives a different puzzle and the same seed always gives the same one.
  - ✅ **12b: Most-constrained first.** `pickMostConstrained` finds the slot with the fewest matching words, and `solve` always fills that one next using a `remaining` list instead of a fixed order. (Shuffling alone made some seeds take 38,000+ tries.)

### Phase 3: Turn the grid into a real crossword
- ✅ **Step 13: Use a player-friendly word list.** `words.txt` is now the words found in both SCOWL size 50 and Spread the Wordlist (score ≥ 50): 38.6k everyday, crossword-approved words instead of ENABLE's `aalii` and `darb`. `loadBlockedWords()` keeps the words in `blocked-words.txt` out. Research and sources are in [WORDLISTS.md](WORDLISTS.md).
- ✅ **Step 13b: Faster word matching.** The friendlier list made puzzles slower (~1 s each). Measuring showed 94% of `findMatches` calls were repeats, so results are now cached, and new patterns are looked up in a Trie (`Trie.java`). 5 puzzles: ~5.5 s → ~0.15 s.
- ✅ **Step 14: Clue numbering.** `App.numberGrid(blackSquares)` scans left→right, top→bottom and numbers every square that starts an Across or Down answer (0 everywhere else).
- ✅ **Step 15: Clues.** No openly licensed clue source exists (see [CLUES.md](CLUES.md)), so each puzzle's ~10 clues are written fresh by Claude through the Claude API, at easy, medium or hard, in a small-daily-crossword style. `ClueWriter.java` builds the prompt, calls the API and checks every clue.
- ✅ **Step 16: A `Puzzle` object.** `Puzzle.java` bundles the grid, numbers, answers, clues, difficulty, mode and seed, and `toJson()` turns it into JSON for the website.

### Phase 4: Make it a website
- ✅ **Step 17: Save generated puzzles.** Generate each day's puzzle once and save it, so the daily puzzle (including Claude's clues) is identical for everyone.
- ✅ **Step 18: Backend API.** A Spring Boot server with `GET /api/daily` and `GET /api/unlimited` that return puzzles as JSON and serve the website.
- ✅ **Step 19: Game board UI.** A web page (HTML/CSS/JavaScript) that draws the 5×5 grid with numbers and lists the Across/Down clues.
- ✅ **Step 20: Controls.** Click to select, type to fill, Backspace, arrow keys, switch Across/Down, highlight the current word and its clue, and jump to the next word.
- ✅ **Step 21: Win detection, timer and score.** A running timer, pause, a "You solved it!" message, and a score from time, difficulty and checks/reveals used.
- ✅ **Step 22: Check and Reveal.** Check or reveal a square, word or the whole puzzle, and mark wrong letters.

### Phase 5: Modes, saving and launch
- ✅ **Step 23: Daily and Unlimited modes.** A home screen to pick a mode. Daily uses the date as the *seed* (same puzzle for everyone) with a countdown; Unlimited makes a new puzzle on demand.
- 🔨 **Step 24: Save progress, stats, scores and settings. ← YOU ARE HERE** Half-finished puzzles, scores, streaks, stats, and a settings screen (difficulty, harder words, timer, theme), all in browser storage.
- ⬜ **Step 25: Tests.** Add JUnit tests for slot finding, pattern matching, numbering and the solver.
- ⬜ **Step 26: Mobile layout and deploy.** Make it work on phones and put the website online, with the API key kept on the server and a rate limit on unlimited mode to keep costs small.

## Running it

Requires **Java 17+** and **Maven**.

```bash
mvn compile
mvn exec:java -Dexec.mainClass=com.crossword.App
```

(`exec:java` uses the `exec-maven-plugin`, which Maven downloads the first time.) Or run `App.java` from VS Code with the ▶ Run button.

> For now the program prints word counts, the slots it found, PASS/FAIL test results and a fully generated 5×5 grid. It isn't playable yet.

To start the website server (Step 18+), then open http://localhost:8080:

```bash
mvn spring-boot:run
```

To also ask Claude for real clues in the tests (costs a little per run, needs the API key below):

```bash
mvn compile exec:java -Dexec.mainClass=com.crossword.App -Dexec.args=live
```

## Claude API key

AI-written clues (Step 15) need an Anthropic API key. **Treat it like a password**: anyone who has it can spend your credits.

1. Create a key at [console.anthropic.com](https://console.anthropic.com) (Settings → API Keys) and add a small amount of credit.
2. Save it **outside this project**, using **your own** PowerShell window (not by pasting it into a chat with Claude or anyone else):
   ```powershell
   New-Item -ItemType Directory -Force "$HOME\.schmoll-crossword" | Out-Null
   notepad "$HOME\.schmoll-crossword\anthropic-api-key.txt"
   ```
   Paste the key as the only line, save, and close Notepad.
3. Run the program. It should print `Claude API key found: yes`. It never prints the key itself.

How the key is protected:
- **Not in git:** the file lives in your home folder, outside the repository. `.gitignore` also blocks `.env` and `*.key` files in case one is ever created here.
- **Not readable by Claude Code:** [.claude/settings.json](.claude/settings.json) has deny rules that stop Claude Code from reading that folder, `.env` / `*.key` files, or running commands that mention them or `ANTHROPIC_API_KEY`.
- **Not in the code:** `ClueWriter.createClient()` loads it at run time.

If a key is ever exposed (pasted somewhere, committed), delete it in the console right away and create a new one.

## Glossary: terms you'll run into

### Crossword terms
| Term | What it means here |
|---|---|
| **Mini** | A small crossword, usually 5×5, that takes a minute or two to solve. |
| **Slot / Entry / Answer** | One place in the grid where a word goes: a start square, a direction (Across/Down) and a length. |
| **Clue number** | The little number in a square that starts an answer. "1-Across" means the answer starting at square 1 going right. |
| **Crossing** | Where an Across answer and a Down answer share a square, and so share a letter. |
| **Pattern** | The letters already in a slot, with `.` for blanks, e.g. `C.T`. |
| **Check / Reveal** | Game helpers: *check* marks wrong letters, *reveal* shows the right ones. |

### Programming terms
| Term | What it means here |
|---|---|
| **Vibe coding** | Building software by describing what you want to an AI and iterating on what it produces. |
| **Generator** | The part of the program that *creates* puzzles, as opposed to the part the player *plays*. |
| **Backtracking** | Try a choice → go deeper → if you hit a dead end, undo the choice and try the next one. This is how the generator fills the grid. |
| **Recursion** | A method that calls itself on a smaller problem. The solver will be recursive. |
| **Heuristic** | A rule of thumb that makes a search faster (e.g. "fill the hardest slot first"). |
| **Seed** | A number that controls "random" choices. The same seed gives the same puzzle, which is how a daily puzzle works. |
| **Maven / `pom.xml`** | Java's build tool and its config file (Java version, libraries, how to build). |
| **Resources folder** | `src/main/resources` holds non-code files (like `words.txt`) bundled with the program. |
| **`HashMap`** | Stores key → value pairs with very fast lookup. Here: word length → list of words. |
| **Lambda** (`k -> new ArrayList<>()`) | A tiny unnamed function you pass around as a value. |
| **JSON** | A text format for data (`{"clue": "Feline pet", "answer": "CAT"}`) that Java and JavaScript can both read. |
| **Backend / Frontend** | Backend = the Java server that makes puzzles. Frontend = the web page the player sees and clicks. |
| **API / Endpoint** | A URL the frontend calls to ask the backend for something, e.g. `/api/puzzle`. |
| **Spring Boot** | A popular Java framework for building web servers/APIs. |

### Git and tools

|---|---|
| **Git / GitHub** | Git tracks every version of your code. GitHub hosts it online. |
| **Commit** | A saved snapshot of your code with a message describing the change. |
| **Push / Pull** | Send your commits to GitHub / bring GitHub's commits down to your computer. |
| **Remote / `origin`** | The online copy of your repo. `origin` is its default nickname. |
| **`.gitignore`** | Files Git should not track (like the `target/` build folder). |
