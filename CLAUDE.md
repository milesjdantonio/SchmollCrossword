# CLAUDE.md

Context for Claude Code when working in this repository.

## What this project is

- **A free mini crossword website** in the style of daily 5×5 puzzles. The player sees a 5×5 grid with numbered squares and Across/Down clues, types in the answers, and wins when the grid is correct (timer, score, check/reveal).
- **Modes:** **Daily** and **Unlimited** (a new puzzle on demand). Difficulty: easy / medium / hard.
  - **Daily design (user's decision):** one grid per date (seed from the date) shared by all three difficulties; each difficulty has its own AI clue set, generated only once (first request) and saved to `puzzles/daily/<date>-<difficulty>.json` (git-ignored), then served from the file so everyone gets identical clues. Solving the daily at any one difficulty completes that day's daily.
- **Saved in the browser:** progress, scores, streaks, stats and settings (difficulty, allow harder words, timer, theme). No accounts.
- The puzzles are **generated by the program**. The Java code is the *puzzle generator*: it fills the grid with words using backtracking, then (later) numbers the squares and attaches clues. A game UI will be built on top of it.
- The user will play and test this, so **answers must be words a normal person can guess**. Obscure dictionary words are bad answers.

## Planned architecture

1. **Generator (Java, done):** word list → grid shape → slots → backtracking fill. Default size is 5×5.
2. **Crossword layer:** clue numbering (done), AI clues (done), and a `Puzzle` object serialized to JSON (current).
3. **Puzzle store:** each daily puzzle is generated once per date and difficulty and saved, so every player gets the identical puzzle and clues.
4. **Backend:** Spring Boot serving `GET /api/daily` and `GET /api/unlimited` (JSON) plus the website files. The API key stays on the server.
5. **Frontend website:** an HTML/CSS/JS board with click/type/arrow-key controls, highlighted word and clue, Across/Down toggle, timer, score, check/reveal, win screen, a mode picker (Daily / Unlimited) and a settings screen. Progress, stats, scores and settings live in `localStorage`.

Don't jump ahead. Build the layers in roadmap order unless the user asks otherwise.

## Code layout

- `App.java` has `main` (a demo: prints word counts and a puzzle for a seed given in `-Dexec.args`, default 1), `findMatches(pattern, wordsByLength)` (returns words fitting a `.`-wildcard pattern, never null) and `loadWords()` (reads `words.txt` from the classpath and returns `Map<Integer, List<String>>` keyed by length; words are uppercased).
- `Trie.java` is a letter tree (`insert`, `match(pattern)` with `.` wildcards, results in alphabetical order). `App.getTrie(wordsByLength)` builds it once; `findMatches` = counters → `matchCache` → Trie. `App.findMatchesByScan` is the user's original Step 7 scan, kept so a test can compare the two.
- `Slot.java` describes one across/down answer position (`startRow`, `startCol`, `length`, `isAcross`).
  - `findAllSlots` / `findAcrossSlots` / `findDownSlots` scan for runs of 3 or more open squares.
  - `getCells()` returns the list of `{row, col}` for the slot.
  - `getPattern(filledGrid)` returns the slot's letters as a string, e.g. `"C.T.."`.
  - `placeWord(filledGrid, word)` writes the word and returns the `{row, col}` squares that were empty before (only those). `removeWord(filledGrid, placedCells)` blanks exactly those squares.
- `src/main/resources/words.txt` holds the words in both SCOWL 50 (english + american words, levels 10–50) and Spread the Wordlist with score ≥ 50, letters a–z only: 38,584 lowercase words, one per line. Blocked words are NOT removed from the file; `loadWords` skips them using `blocked-words.txt` (54 lowercase words, sorted, one per line; 10 of them appear in words.txt). Keep the blocklist test count in `WordListTest` in sync with the file. `too-hard-words.txt` (Step 13c, ~26,000 words; leaves 3,930 three-to-five-letter answers) lists words harder than everyday level: all SCOWL level 40/50 words except a keep list, plus (since the user asked for easier words) all level-35 words except a hand-picked everyday keep list; `loadWords()` skips them while `App.SKIP_TOO_HARD_WORDS` is true (default), and `loadWords(false)` keeps them. Offensive words are always skipped. The list was hand-judged by Claude from SCOWL levels (all level 40/50 words except a keep list of everyday words, plus archaic/crossword-only level-35 words); never use the NYT Wordle list. `WORDLIST-NOTICE.txt` gives credits and the CC BY-NC-SA 4.0 license; `SCOWL-Copyright.txt` is SCOWL's notice. Tests (`WordListTest`, `SolverTest`) have expected counts tied to this list (e.g. `C.T.` = 6, `.....` = 3701 after blocking and too-hard filtering), so update them if the list changes.

## Conventions

- Grids: `boolean[][] blackSquares` (`true` = black), `char[][] filledGrid` (`'.'` = empty). Grids are square (`size = blackSquares.length`).
- The minimum answer length is 3 (same as NYT).
- Package `com.crossword`. Fields are package-private, with no getters/setters so far. Match this simple style unless the user asks to refactor.
- `target/` is build output and is git-ignored.
