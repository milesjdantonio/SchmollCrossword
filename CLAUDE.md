## What this project is

- **A playable mini crossword game** in the style of daily 5×5 puzzles. The player sees a 5×5 grid with numbered squares and Across/Down clues, types in the answers, and wins when the grid is correct (with a timer, check/reveal, and so on).
- The puzzles are **generated by the program**. The Java code is the *puzzle generator*: it fills the grid with words using backtracking, then (later) numbers the squares and attaches clues. A game UI will be built on top of it.
- The user will play and test this, so **answers must be words a normal person can guess**. Obscure dictionary words are bad answers.

## Planned architecture

1. **Generator (Java, current work):** word list → grid shape → slots → backtracking fill. Default size is 5×5, the classic Mini.
2. **Crossword layer:** NYT-style clue numbering, a clue for each answer, and a `Puzzle` object serialized to JSON.
3. **Backend:** a small Java web server (likely Spring Boot) that serves puzzles, e.g. `GET /api/puzzle`.
4. **Frontend:** an HTML/CSS/JS game board with click/type/arrow-key controls, a highlighted current word and clue, an Across/Down toggle, a timer, check/reveal, and a win screen.
5. **Daily puzzle:** the date is used as the random seed so everyone gets the same puzzle on the same day.

Don't jump ahead. Build the layers in roadmap order unless the user asks otherwise.

## Code layout

- `App.java` has `main` (prints word counts for lengths 3–7, builds a hard-coded 5×5 grid with black squares in the top-right and bottom-left corners, places a few test letters, prints every slot with its pattern, and runs `testFindMatches` PASS/FAIL checks), `findMatches(pattern, wordsByLength)` (returns words fitting a `.`-wildcard pattern, never null) and `loadWords()` (reads `words.txt` from the classpath and returns `Map<Integer, List<String>>` keyed by length; words are uppercased).
- `Slot.java` describes one across/down answer position (`startRow`, `startCol`, `length`, `isAcross`).
  - `findAllSlots` / `findAcrossSlots` / `findDownSlots` scan for runs of 3 or more open squares.
  - `getCells()` returns the list of `{row, col}` for the slot.
  - `getPattern(filledGrid)` returns the slot's letters as a string, e.g. `"C.T.."`.
  - `placeWord(filledGrid, word)` writes the word and returns the `{row, col}` squares that were empty before (only those). `removeWord(filledGrid, placedCells)` blanks exactly those squares.
- `src/main/resources/words.txt` holds the words in both SCOWL 50 (english + american words, levels 10–50) and Spread the Wordlist with score ≥ 50, letters a–z only: 38,584 lowercase words, one per line. Blocked words are NOT removed from the file; `loadWords` skips them using `blocked-words.txt` (52 lowercase words, sorted, one per line; 10 of them appear in words.txt). Keep the blocklist test count in `main` in sync with the file. `WORDLIST-NOTICE.txt` gives credits and the CC BY-NC-SA 4.0 license; `SCOWL-Copyright.txt` is SCOWL's notice. Tests in `main` have expected counts tied to this list (e.g. `C.T.` = 7, `.....` = 4014 after blocking), so update them if the list changes.

## Conventions

- Grids: `boolean[][] blackSquares` (`true` = black), `char[][] filledGrid` (`'.'` = empty). Grids are square (`size = blackSquares.length`).
- The minimum answer length is 3 (same as NYT).
- Package `com.crossword`. Fields are package-private, with no getters/setters so far. Match this simple style unless the user asks to refactor.
- `target/` is build output and is git-ignored.
